# deepseek 件：DeepSeek 命令管道

背景一句：2026-09-20 NAS 监控转向时拍板——**模型不进判定、只进编辑**；DeepSeek 的 key 从
ugreen-nas-config 的 `.deepseek-key` 搬家到 gwb，做成独立可调用的件，news-links 是第一个消费者，
将来任何件要用模型都走它，全工作台一把钥匙一个出口。

## 验收

- [ ] `deepseek.chat`：入参 `{prompt, system?, json_mode?, timeout?}`，成功回 `{text, usage}`；失败回结构化错误 `{error: timeout|rate_limit|bad_key|bad_response, detail}`，不抛裸异常
- [ ] key 走 `gwbSettings.define`（条目只写 id），缺 key 回结构化 bad_key；key 正本只在这一处，别处不存
- [ ] 每次调用记账 `{at, caller, model, tokens}` 落 gwbData（caller 由调用方入参自带，件不嗅探），`deepseek.usage` 按调用方汇总可查
- [ ] 件内零消费方策略：不重试、不熔断、不缓存——降级决策全在调用方
- [ ] 隔离 home 挂上 ACTIVE；真调一次（真 key 成功、假 key 验 bad_key 路径，两个都算数）
- [ ] `pnpm check` 全绿

## 方案

node 半单命令件，无 UI。HTTP 直调 DeepSeek 的 OpenAI 兼容端点（国内直连，PC 侧真调通过——
2026-08-09 ugreen-nas-config 的 pc 验收实测过同通道）。journal 落 gwbData 文档、滚动剪枝。
模板的示例窗格与 ping 命令改造时删掉。发版后 default 装它，news-links 的调用才有着落。
