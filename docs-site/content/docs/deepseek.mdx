# deepseek 件

**本页回答**：deepseek 这件管什么、不知道什么、接口长什么样、怎么单独测。

## 管什么

把 DeepSeek 调用做成全工作台共用的哑管道：一条 `deepseek.chat` 原样发、原样回（四类结构化错误），一条 `deepseek.usage` 按调用方汇总 token 记账。key / model / base-url 住设置，key 正本只在这一件。**不带任何消费方策略**——不重试、不熔断、不缓存，降级决策全在调用方（这是硬边界：第二个消费者不能被第一个消费者的策略绑架）。

## 不知道什么

不知道谁在调它（caller 由调用方入参自报，件不嗅探）、不知道调用方该怎么降级、不知道 prompt 与应答内容（正文不进日志，日志只有 caller / model / token 数）、不做 UI（无窗格）。

## 数据结构

记账文档 `journal.json`（gwbData）：条目数组，每条 `{ at, caller, model, ok, error?, usage? }`，尾部裁剪保持最多 500 条。

## 提供的接口

命令面两条（归属 `@godcreator/gwb-deepseek`）：`deepseek.chat`、`deepseek.usage`，参数形状写在命令 description 里（agent 看得见的就是那一句）；语义正本住随包 skill「deepseek」。

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `gwbCommands` | 注册两条命令 | gwb-commands | 自搭替身（tests/plugin.test.ts） |
| `gwbSettings` | 定义并读 api-key / model / base-url | gwb-settings | 自搭替身 |
| `gwbData` | 记账文档读写 | gwb-data | 自搭替身 |
| `gwbSkills`（局部注入） | 挂随包说明书 | gwb-skills | 自搭替身 |

## 怎么单独测

纯逻辑全在 core.ts（参数收窄 / 请求组装 / 错误归类 / 应答解析 / 记账裁剪汇总），喂输入看输出、不碰网络；挂载面用自搭替身断言命令 / 设置 / 说明书登记与 bad_key 短路；真调一次走 slow 档（`DEEPSEEK_API_KEY` 环境变量给 key，`pnpm test:all` 才跑）。
