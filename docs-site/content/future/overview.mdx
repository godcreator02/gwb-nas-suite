# 未来

**本页回答**：`gwb-nas-suite` 往哪儿去、什么明确不做、路线图分几个阶段、现在在哪一个。

## 愿景

机主的日常信息面板全部放在 gwb 里：NAS 今天健不健康一眼就能看到（出没出事都看得见，报告程序自己停了也看得见）、今天有什么值得点进去看的链接一张清单、任何插件要用模型都走同一个命令、用同一份 API key。NAS 侧只生产数据，消费与呈现全在桌面。

## 明确不做

- 不做微信推送（2026-09-20 决定退役；「异常日才推」的逻辑留在 ugreen-nas-config 的 push 代码里，将来要恢复在那边做，不在本仓）
- 不做实时告警与手机推送——离开桌面时的告警归将来的鸿蒙手机告警端，与看板分工
- 不在 NAS 上渲染、不建静态站与 m 子域——视图每次从 JSON 现画，「换样式全站变」天然成立
- 不搬运正文全文——精选只出「选哪些 + 一句理由」，正文永远在源头，链接直达
- 体检判定不接模型——判定要确定性可复现（阈值模板），模型只用在精选
- 不做多用户水位与多机同步——只服务机主一人

## 路线图

| 阶段 | 目标 | 完成的标志 |
| --- | --- | --- |
| 1 | deepseek 插件：命令管道 + 记账，API key 只存这一处 | 验收全过，发版装进 default |
| 2 | news-links 插件：取数 + 水位 + 精选 + 阅读器 | spec/news-links 验收全勾 |
| 3 | nas-board 插件：拉取 + 看板 + 看门狗 | spec/nas-board 验收全勾（回放数据） |
| 4 | NAS 侧部署（在 ugreen-nas-config 做）：report 容器收窄部署、旧推送下线 | 那边的文档与草稿都已完成 |
| 5 | 三个插件的正式版都装进 default，用真实数据运行一周 | 面板日常可用 |

## 当前阶段

现在在第 2 阶段：deepseek 插件已发版装进 default，真实调用与隔离 home 验收全过。
