# 未来

**本页回答**：`gwb-nas-suite` 往哪儿去、什么明确不做、路线图分几个阶段、现在在哪一个。
这一区常改；现状区一字不写未来，未来的话全在这儿。

## 愿景

机主的日常信息面板全部长在 gwb 里：NAS 今天健不健康一眼看穿（出不出事都看得见，报告器自己死了也看得见）、今天有什么值得点进去看的链接一张清单、任何件要用模型都有一个出口一把钥匙。NAS 侧只生产数据，消费与呈现全在桌面。

## 明确不做

一行一条，写清为什么不做——「不做」也是决定，推翻它要落一张轨迹卡。

- 不做微信推送（2026-09-20 拍板退役；「异常日才推」的后门逻辑留在 ugreen-nas-config 的 push 代码里，将来要复活在那边做，不在本仓）
- 不做实时告警与随身推送——离桌告警是将来的鸿蒙告警随身端那条线的活，与看板分工
- 不在 NAS 上渲染、不建静态站与 m 子域——视图每次从 JSON 现画，「换样式全站变」天然成立
- 不搬运正文全文——精选只出「选哪些 + 一句理由」，正文永远在源头，链接直达
- 体检判定不接模型——判定要确定性可复现（阈值模板），模型只进编辑（精选）
- 不做多用户水位与多机同步——只服务机主一人

## 路线图

| 1 | deepseek 件：命令管道 + 记账，key 正本搬家 | spec/deepseek 验收全勾，发版装 default |

## 当前阶段

现在在第 2 阶段（2026-09-20：deepseek 件 0.1.1 已发版装 default，真调与隔离 home 验收全过）。阶段切换时：把新阶段写在这儿，落一张轨迹卡，顺手复审上面「明确不做」的每一条还成不成立。
