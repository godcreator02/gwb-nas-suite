**本页回答**：`gwb-nas-suite` 往哪儿去、路线图分几个阶段、现在在哪一个。明确不做的事是此刻的边界，写在现状区：整个仓的在[入口页](/docs)，各插件的在各自首页。

## 愿景

机主的日常信息都在工作台里看：NAS 今天健不健康一眼就能看到（出了事看得见，报告程序自己停了也看得见）；今天有哪些值得点进去看的链接，一张清单；任何插件要用模型都走同一条命令、用同一份 API key。NAS 侧只生产数据，查看与呈现全在桌面。

## 路线图

| 阶段 | 目标 | 完成的标志 |
| --- | --- | --- |
| 1 | deepseek 插件：原样转发 + 记账，API key 只存这一处 | 验收全过，发版装进 default |
| 2 | news-links 插件：取数 + 水位 + 精选 + 阅读器 | [news-links 实施方案](/future/spec/news-links) 验收全勾 |
| 3 | nas-board 插件：拉取 + 看板 + 看门狗 | [nas-board 实施方案](/future/spec/nas-board) 验收全勾（用回放数据） |
| 4 | NAS 侧部署（在 ugreen-nas-config 做）：report 容器只保留采集、判定、归档，旧推送下线 | 那边的文档与草稿都已完成 |
| 5 | 三个插件的正式版都装进 default，用真实数据运行一周 | 日常能用 |

## 当前阶段

在第 2 阶段：deepseek 插件已发版装进 default，真实调用与隔离 home 验收都过了。三个插件的依赖刚跟到内核 0.7.2、命令总线 0.5.2，nas-board 与 news-links 的外壳跟到 0.15.0，还没在隔离 home 里验过、没发版。
